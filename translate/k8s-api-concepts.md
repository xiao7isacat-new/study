## 1. 选定的主文档

[Kubernetes API Concepts，固定 v1.32 页面](https://v1-32.docs.kubernetes.io/docs/reference/using-api/api-concepts/)。只翻正文，跳过网页导航、页脚和代码中的标识符。

选择理由：你已追过 client-go 的 List、Do、Into，这篇文档把对应的接口、请求/响应、资源对象、编码、列表、变更通知、缓存、版本和更新行为连起来。技术背景有一部分已经熟悉，可以把精力放到英文表达上。它是 API 机制文档，不是逐行源码教程；后续再把读懂的表达迁移到源码注释。

一篇文档不能覆盖整个计算机专业的大多数英语词汇。这里先建立与你工作有关的高频词、搭配和句式，不承诺词汇覆盖百分比。GPU 硬件、驱动和网络术语在之后的专项阅读中补。

## 2. 每天怎么做

先试行 7 天：每天 15 分钟，起步 1～2 句，通常约 10～40 个英文词。遇到长句可分两天处理；当天只分析透一句也算完成。用时到就记录停止位置，不要求完成整段或整页。

| 时间 | 动作 | 留下什么 |
| --- | --- | --- |
| 0～2 分钟 | 重读上次的一句，先尝试不看译文理解 | 仍不认识的词或句子 |
| 2～5 分钟 | 读本次 1～2 句，找主语、谓语及条件/否定；查影响理解的词 | 本句结构与词义 |
| 5～12 分钟 | 自己翻译，保留不确定处；太难就只做一句 | 你的初稿 |
| 12～15 分钟 | 重读英文，对照是否漏了条件、范围或指代；记最多 3 个词/搭配 | 一处疑问及下次位置 |

不需要先补完四级单词，也不需要同时从头学习整套语法。先围绕实际句子补足理解所需的知识。查词允许；整段机翻或官方中文可以在自己尝试后用于核对，保留初稿才看得见进步。

词汇按语境记录。例如 state 在技术文档里常表示“状态”，return 在函数描述中常表示“返回”；不要只背脱离句子的第一个中文释义。supports、supported 等形式可以归到 support 下，连同原句中的用法一起记录。

## 3. 与原来 14 小时计划的关系

15 分钟 × 7 天 = 每周 105 分钟，计入原来的源码/Go/容器机制 5 小时阅读学习预算，其中其余约 3 小时 15 分钟用于源码、Go 和机制学习；不把 105 分钟再叠加到 14 小时之外。同一段文档同时服务技术学习和英文训练，只计时一次。

原来没有核心学习任务的日子，这 15 分钟是你本次主动增加的小任务；对应时间从本周该类学习预算中调剂。GPU、项目与复盘预算暂不增加。第一周若明显挤压源码实验，先把每日练习缩到 5～10 分钟，保留每天接触英文，不通过额外加班追赶字数。

## 4. 第一轮七次练习

下面的 E1～E7 是英文练习序号，不是原第 1～7 天技术任务，也没有自动指定实际日期。前一次没完成，下次从停止位置继续；不会积累补交债务。

| 次数 | 在原文中的位置 | 本次范围 | 练习重点 |
| --- | --- | --- | --- |
| E1 | 大标题下、术语小节之前的开头第一段 | 第一句 | API 是什么接口；找 is 和 provided 的关系；只需自己尝试翻译 |
| E2 | 同一段 | 第二句 | supports 后的动作列表；识别读取、创建、更新、删除对应的英文 |
| E3 | 开篇介绍中讲 watches 的两句 | 以 15 分钟内能完成的句数为准 | watch 作为技术动作，关注句子的主语和用途说明 |
| E4 | 开篇介绍中讲 list、缓存与同步的一句 | 一句 | so that 引出的目的，以及并列动作 |
| E5 | 术语小节的开头及前两条列表 | 最多两条，不翻后面的长段 | resource type、kind，以及 used/called 等表达 |
| E6 | 同一术语列表中 collection、单个 resource 的两条 | 最多两条 | type 与 instance、单个与集合的区别 |
| E7 | 回看 E1～E6 | 不增加新段落 | 选三句遮住译文重读；写出还卡在哪里 |

为控制难度，开篇有关子资源、细粒度授权的长句及术语列表最后一条暂缓，之后回补；不是认定已经翻译。若 E3～E6 的指定范围当天过多，按实际停止处顺延，不需要追上表格。

之后按术语 → 对象名称与 API 动词 → 资源路径 → HTTP 内容类型与 JSON → Watch/List 与分页 → 更新与版本的顺序推进。先跳过二进制格式细节、大段代码和较新的高级能力；学到相关机制再返回。整篇不设强制翻完日期。

## 5. 优先积累哪类词

以下是阅读时的关注方向，不是今天要背完的清单。以实际遇到的原句为准。

| 类型 | 示例 | 要练的能力 |
| --- | --- | --- |
| 动作 | retrieve、create、update、delete、return | 谁对什么执行了什么动作 |
| 对象与结构 | resource、object、instance、collection、interface | 区分类型、实例和集合 |
| 客户端与协议 | client、server、request、response、header、body | 分清请求方向和数据位置 |
| 状态与数据 | state、version、cache、encode、decode | 读懂状态跟踪及数据转换 |
| 条件与限定 | if、when、only、not、may、must | 不漏译条件、否定、范围与强制程度 |

## 6. 如何交给助手点评

每次贴 1～2 句的原文、自己的译文和最不确定的一处即可。助手先指出影响意思的误译，尤其是条件/否定/指代；再解释必要的词义或句法，区分英文理解错误和技术概念不熟。修改参考译文应放在点评中，不覆盖你的初稿。

本任务沿用一个文件记录，不每天新增一份英文 review。每次最多追问两题；没有提交译文就不登记完成，也不因收到解释直接登记掌握。

第一周先看能否找出主语和动作、保留条件与否定、重读时减少查词。速度和词数先作为观察指标，不能为了字数跳过理解。七次练习后再按实际表现调整份量。
