### A3. 实现并修改 context 小实验，40 分钟

将下面程序保存到单独的练习目录作为 `main.go`。它只使用标准库，可以脱离集群运行：

```go
package main

import (
    "context"
    "fmt"
    "time"
)

func work(ctx context.Context, cost time.Duration) error {
    timer := time.NewTimer(cost)
    defer timer.Stop()
    select {
    case <-ctx.Done():
        return fmt.Errorf("work stopped: %w", ctx.Err())
    case <-timer.C:
        return nil
    }
}

func main() {
    ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
    defer cancel()
    err := work(ctx, 300*time.Millisecond)
    fmt.Printf("result: %v\n", err)
}
```

按顺序做三次实验，每次先预测再运行：

在该练习目录用 `go run main.go` 执行；不要把它与 CLI 的 `main.go` 放进同一个包目录。

1. 保持 100ms 超时、300ms 工作量，记录结果与大致耗时。
2. 将超时改为 500ms，其他不变，记录差异。
3. 在调用 `work` 前主动 `cancel()`，记录错误。

完成标准：能解释 `ctx.Done()`、`ctx.Err()`、`defer cancel()`、错误包装 `%w` 的用途。取消需要被下游观察；仅创建 context 不会自动中断任意一段代码。具体耗时允许调度误差，不以毫秒级精度验收。

### S2. CLI 第 1 步：最小 Node List，45 分钟

在 `week01/project/main.go` 写一个能运行的最小程序。下面是起点，不是最终交付代码：

```go
package main

import (
    "context"
    "flag"
    "fmt"
    "os"
    "time"

    metav1 "k8s.io/apimachinery/pkg/apis/meta/v1"
    "k8s.io/client-go/kubernetes"
    "k8s.io/client-go/tools/clientcmd"
)

func run() error {
    kubeconfig := flag.String("kubeconfig", "", "path to one kubeconfig file")
    flag.Parse()
    if *kubeconfig == "" {
        return fmt.Errorf("--kubeconfig is required")
    }
    cfg, err := clientcmd.BuildConfigFromFlags("", *kubeconfig)
    if err != nil {
        return fmt.Errorf("load config: %w", err)
    }
    client, err := kubernetes.NewForConfig(cfg)
    if err != nil {
        return fmt.Errorf("create client: %w", err)
    }
    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()
    nodes, err := client.CoreV1().Nodes().List(ctx, metav1.ListOptions{})
    if err != nil {
        return fmt.Errorf("list nodes: %w", err)
    }
    fmt.Printf("nodes=%d\n", len(nodes.Items))
    return nil
}

func main() {
    if err := run(); err != nil {
        fmt.Fprintln(os.Stderr, err)
        os.Exit(1)
    }
}
```

这个起点使用所指定 kubeconfig 的默认 context；下一步增加显式 context 选择。运行前确认该文件默认 context 是实验环境。

1. 用 `flag.String` 增加 `--context`、`--namespace`；用 `flag.Duration` 增加 `--timeout`，默认 5s，拒绝零或负值。
2. 支持显式 kubeconfig/context：从下面这段替换配置创建部分，理解 overrides 和 loading rules 的职责。
3. 使用同一个请求 context 查询 Node 和目标 namespace 的 Pod，表示本次采集共享一个时间预算。
4. `Pods(namespace).List` 后先打印数量，和同范围 kubectl 结果比较；暂不格式化所有字段。

参数声明全部放在 `flag.Parse()` 之前。例如保留起点的 `kubeconfig := flag.String(...)`，再声明 `contextName := flag.String("context", "", "kubeconfig context")`、`namespace := flag.String("namespace", "default", "one namespace")`、`timeout := flag.Duration("timeout", 5*time.Second, "API collection timeout")`。这些变量是指针，使用值时要解引用；校验 `*namespace != ""`、`*timeout > 0`，并将起点的 5 秒替换为 `*timeout`。

配置创建的关键片段沿用这些指针变量：

```go
rules := clientcmd.NewDefaultClientConfigLoadingRules()
rules.ExplicitPath = *kubeconfig
overrides := &clientcmd.ConfigOverrides{CurrentContext: *contextName}
cfg, err := clientcmd.NewNonInteractiveDeferredLoadingClientConfig(rules, overrides).ClientConfig()
```

查询 Pod 的关键调用：

```go
pods, err := client.CoreV1().Pods(*namespace).List(ctx, metav1.ListOptions{})
```

本周 namespace 必须非空，避免空字符串隐式变成全 namespace 查询。若鉴权插件需要外部登录，先记录 kubeconfig 的认证方式和报错；exec 登录流程未必受 API 请求 context 的全部约束，不把它当成本周超时机制的可靠故障实验。

## 7. 周末第 2 块：完成 CLI 与复盘，4 小时

### U1. CLI 第 3 步：提取 Node/Pod 字段，45 分钟

定义自己的输出结构，建议包含：

```text
Report
  observed_at
  nodes[]
    name
    gpu_capacity          // 无资源键时 null
    gpu_allocatable       // 无资源键时 null
  pods[]
    namespace, name, node_name, phase
    containers[]
      name, gpu_request, gpu_limit
```

先展示 `spec.containers` 中每个普通容器的请求/限制；initContainers、overhead、有效 Pod 请求及节点剩余量的计算留到后续。没有资源键和资源数值为零使用不同表示。

GPU 字段从 `ResourceList` 读取，按 quantity 转字符串。关键辅助函数如下，可放在同一包；导入 `corev1 "k8s.io/api/core/v1"`：

```go
func gpuQuantity(resources corev1.ResourceList) *string {
    q, ok := resources[corev1.ResourceName("nvidia.com/gpu")]
    if !ok {
        return nil
    }
    value := q.String()
    return &value
}
```

对应字段使用 `*string`，保留 JSON 的 null，不给它加 `omitempty`。从 `node.Status.Capacity`、`node.Status.Allocatable`、`container.Resources.Requests`、`Limits` 分别提取。

读 [Nodes 的 Capacity and Allocatable](https://kubernetes.io/docs/concepts/architecture/nodes/#capacity-and-allocatable) 与 [Schedule GPUs 的资源请求部分](https://kubernetes.io/docs/tasks/manage-gpus/scheduling-gpus/)，只核对你正在展示的字段。

要讲清：allocatable 不是尚未分配的剩余量；Node 未发布资源键，只能说明该键未发布，不能据此断言物理机没 GPU。此版本展示 API 返回值，不自行模拟 admission 的默认填充规则。

### U2. CLI 第 4 步：JSON 与错误处理，30 分钟

使用 [encoding/json 的 Encoder](https://pkg.go.dev/encoding/json#Encoder.Encode)：

```go
encoder := json.NewEncoder(os.Stdout)
encoder.SetIndent("", "  ")
if err := encoder.Encode(report); err != nil {
    return fmt.Errorf("encode report: %w", err)
}
```

约定：成功时 stdout 只有一个 JSON 文档；诊断写 stderr；失败时返回非零退出码。查询 Node 或 Pod 任一失败时，v0.1 整体失败，不将另一部分静默当作完整报告。给 slice 初始化为空数组，避免“空集合”有时输出 null、有时输出 []。

建议保持三个文件：`main.go` 负责参数和退出，`collect.go` 负责 API 查询，`report.go` 负责输出结构与转换。第一周允许先单文件，功能稳定后再拆。无需为了接口练习先制造一套通用框架。


没有 Python 时用现有 JSON 工具检查。以下为合成的格式示例，不是你的环境实测结果：

```json
  "observed_at": "示例时间",
  "nodes": [{"name": "example-cpu-node", "gpu_capacity": null, "gpu_allocatable": null}],
```

用下面 6 项填写实际结果：

| 用例 | 验证方法 | 预期 |
| --- | --- | --- |
| 正常读取 | 小实验集群、已存在 namespace；与 kubectl 同范围比较 | 名称和资源字段匹配；动态对象变化允许分别解释 |

## 8. 第一次实现遇到问题，怎样排查

| 现象 | 先检查 | 不要立即做的推断 |
| --- | --- | --- |
| go mod 下载失败 | Go 版本、代理、DNS、网络与完整报错 | client-go 源码有问题 |
| kubeconfig 找不到/加载失败 | 显式路径、文件权限、指定 context 是否存在 | 集群故障 |
| x509 错误 | server 名称、证书链、时间、配置是否匹配 | 通过跳过 TLS 校验解决学习任务 |
| Forbidden | 操作动词、资源、namespace、账号；用 auth can-i 对照 | 网络不通 |
| timeout | 是构建/认证/HTTP 还是服务端慢；context 是否传到实际调用 | 随意把所有超时调很大 |
| Node 无 GPU 键 | 是否为 GPU 机器、驱动/插件是否部署并发布资源 | 机器一定没卡 |
| JSON 解析失败 | stdout 是否混入调试日志、字符串拼接是否出错 | JSON 库有问题 |

把实际错误原文、触发命令、环境版本、你已经检查的事实一并发来，才能高效复盘。
